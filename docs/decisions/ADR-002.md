# ADR-002: Service Request, Quote, and Work Execution

- **Status:** PROPOSED
- **Date:** 2026-11-13 (baseline documentation)
- **Decision owner:** Not recorded

## Context and problem

The current `services` app has `ServiceRequest` and `ServiceRequestQuote`; work execution/completion behavior is coupled across service and order concepts. No canonical WorkOrder model was found in the inventory. A single object/status should not represent customer need, commercial offer, and authorized execution.

## Proposed direction

Keep `ServiceRequest` as demand/intake, `ServiceQuote` (currently represented by `ServiceRequestQuote`) as a versioned commercial offer, and a future WorkOrder as authorized execution. Approval must identify the exact scope/price/terms version. Customer acceptance and financial completion remain separate.

## Consequences and open decisions

Requires state and permission mapping, API compatibility plan, quote version/snapshot policy, and decision on a WorkOrder boundary. Exact status transitions, invitation authority, validity, acceptance, rework, cancellation, warranty, and emergency exceptions are unresolved. Do not create a WorkOrder feature during Phase 0 freeze.

## Alternatives

- Continue one overloaded request/order lifecycle: simpler short-term, but ambiguous state and audit semantics.
- Separate commercial and execution records with explicit linkage: proposed; migration and operational policies must be resolved first.
